# Open questions

Points that need a decision, decisions already taken (kept for the record), and what I changed instead of only adding. The default in use is stated in each open item.

## Open

1. **Criterion for "the best lambda" (from B) and "the best architecture of A" (for E).** Both choices are made by looking at results, so they should not use the test set. Otherwise the test set selects the configuration that is then reported on it. Proposed default:
   - **Best architecture of A:** the lowest validation MSE of seed 0, `best_val_mse` in `summary.json`.
   - **Best lambda:** it can't be "lowest MSE", because MSE alone favours small lambda. It needs a stated trade-off, for example the largest lambda whose validation MSE is at most X% above lambda = 0. Validation LPIPS is logged every epoch; spectral metrics on validation would need a small addition to `evaluate_run.py` (`--split val`). Which criterion do you want, and on which split?
2. **Should `results/` be versioned?** It is untracked: today it holds the 14 baselines (22 MB), and the campaign will add the runs. `results_pilot/` is versioned without `*.pt`/`*.npz`. Options:
   - (a) same rule for `results/`, versioning `config.json`, `summary.json`, CSVs and `eval_summary.json`, but not `spectra.npz`. `stats.py` needs `spectra.npz`; it can be regenerated by re-evaluating `best.pt`.
   - (b) also `spectra.npz` (~1.3 MB per run, about 80 MB for the campaign).
   - (c) leave it untracked and keep the `collect_results.py` zip.
   - Default: (c). Note that `git status` therefore always lists `results/` as untracked. The clean-tree guard only looks at tracked files, so it is unaffected.
3. **Queue `fase1` at the maximum length.** At 150 epochs per run it takes 62.7 GPU-h (one 70 h block); at 300 epochs, about 125 h (two blocks). Relaunching the same command continues it. Recompute with `gpu_hours.py --measured results` after A seed 0, before deciding whether to split B into its own queue.

## Changed instead of only added

9. `scripts/make_block_c.py`: `--sweep-arch` now takes one or more architectures and skips seed 0 of each. A single value works as before (14 configs); two give 13.
10. `train.py`: the optimizer receives only parameters with `requires_grad`. For single-stage runs, where every parameter is trainable, the list is identical; in multistage it excludes the frozen earlier stages. `evaluate_run.load_model` gained a branch for multistage runs; other runs take the old path.
11. `scripts/blocks.py:write_config` gained optional `run_name` and `extra` arguments. With the defaults it writes exactly the same files: blocks A and B regenerated byte-identical.
12. `scripts/gpu_hours.py`:
    - It follows the decided composition (D = 3 runs; regime B = 13 runs as in R2).
    - It no longer prints the proposed cuts, which were rejected.
    - It adds `--measured` and the per-queue table.
    - Block E counts stages 2-4 plus a control of stage 1 + stage 2 epochs. The earlier version counted stage 1 again and gave the control the length of all 4 stages, overestimating E by ~40%.
13. Multistage stage 2 of SRNO/SoFoNO: the old `train_multistage.py` built f_2 with the original models, which add a bilinear skip of x, so the old stage 2 predicted `x + g(x)` as the normalized residual. The new stages have no skip (`RESIDUAL: false`). Old and new stage-2 results are therefore not comparable for the operators.
14. `configs/D/`: the PRUSR and SoFoNO YAMLs were moved, not deleted, to `configs/D_optional/`.
15. Legacy multistage files moved, not deleted, from the repository root, `models/`, `configs/` and `notebooks/` to `archive/legacy_multistage/`, keeping their relative paths.
